# 企业数据仓库管理平台

面向企业数据团队的一站式数据仓库建设与管理平台。覆盖原始数据落地、多层清洗转换、维度建模、事实建模、分区治理、质量校验、血缘追踪与历史补数的完整数仓链路。

这是一个前后端分离的管理平台：前端 React + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 字段业务含义版本发布

元数据记录的字段业务含义、统计信息、负责人按版本发布管理（`field_version` 模块），
解决多次发布后含义无法追溯、血缘引用旧说明、演进记录只剩最后一份变更的问题。

### 版本生命周期

- 每次修改业务含义、统计信息或负责人都会生成一条新草稿，状态按
  **草稿 → 待审批 → 已生效** 推进；已生效版本是不可变快照，任何修正只能再发新版本。
- 同一元数据记录同一时刻只允许一个开放版本（草稿或待审批）；并发提交审批时
  通过进程锁加落库前复检，保证只有一个待办真正入库。
- 发布时记录生效时间与发布批次（正常发布 `REL-xxxx`，晚到回填 `BF-xxxx`）。

### 生效区间与晚到回填

- 发布时自动把版本切进时间线：更早版本的失效时间收窄到新生效日期，新版本的
  失效时间取更晚版本的最早生效日期，时间线首尾相接。
- 晚到的说明修正用**回填发布**插入历史生效区间，旧已生效版本保留不变；
  历史批次仍可通过版本引用回看当时说明。
- 同一生效时间的两个版本构成真冲突，按 **生效时间 → 发布批次 → 版本完整度**
  定优先级；解析目标日期时以「能够覆盖目标日期且已生效」的版本为准，可通过
  `GET /api/field-versions/records/{id}/resolve?target_date=...` 查询。

### 引用一致性

- 血缘节点（`lineage.field_version_id`）与演进记录（`catalog.field_version_id`）
  只保存版本引用，展示时由字段版本服务统一解析快照。
- 因此元数据记录页、血缘页、演进记录中的字段含义、版本号与更新时间始终一致；
  新版本发布不会改变历史引用指向的快照。
- 每次发布自动生成一条带版本引用的演进留痕，血缘节点可通过
  `POST /api/lineage/{id}/bind-version` 绑定字段版本。
